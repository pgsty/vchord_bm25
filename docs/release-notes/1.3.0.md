# vchord_bm25 1.3.0

- Reduce Generic WAL records during index builds and segment rebuilds by batching posting checkpoints across terms. Parallel participants report build progress every 1,024 rows and at the end of their scans.
- Share the mapping sort budget across the leader and launched workers during index creation. Each participant uses at most its share of `maintenance_work_mem` and 64 MiB. PostgreSQL 17–19 supply the worker request directly.
- Keep exact combined corpus statistics for sealed and growing documents. Scalar scoring reuses index metadata within an execution. Ranked scans retain positive growing candidates and read zero-score and NULL rows as pagination reaches them, skipping exhausted positive growing candidates on later batches.
- Price first-batch preparation separately from repeated posting scans so PostgreSQL can use an ordered BM25 scan for selective Top-K queries.
- Let index owners enable whole-index statistics under row security with `shared_corpus_stats`. The default is off. Scoring checks the caller's corpus privileges on scalar, index and view paths. Column grants can cover simple index expressions and partial predicates. PostgreSQL applies row policies before returning rows.
- Prefilter repeatable correlated subqueries over plain heap or B-tree scans, including scalar `count(*)`. PostgreSQL evaluates volatile subqueries and security-sensitive filters.
- Delay scratch-file creation until a rebuild is needed. Remove up to three retired pages from their chain in one WAL record and publish free-space hints after the record completes.
- Attach the source ZIP with PGXN metadata and a SHA-256 checksum to the GitHub release. Uploading it to PGXN requires configured credentials.

Install the matching library and SQL files, restart PostgreSQL, and run `ALTER EXTENSION vchord_bm25 UPDATE;` in each database. Versions 1.0.0, 1.1.0 and 1.2.0 keep their format-4 indexes during the upgrade. PostgreSQL 15–19 on x86_64 and aarch64 are supported. PostgreSQL 14 installations must upgrade the server first. The 0.3.x engine requires data migration and index rebuilding.

Before reverting the library, run `ALTER INDEX ... RESET (shared_corpus_stats)` on every index where the option was explicitly set, including explicit `off` values. The SQL upgrade path is forward-only.
