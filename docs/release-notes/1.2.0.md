# vchord_bm25 1.2.0

Version 1.2.0 supports PostgreSQL 15–19 on `x86_64` and `aarch64`. Building the extension and its SQL generator requires Rust 1.100.0 or later. Both use pgrx 0.20.1.

- Update the locked `url` dependency to 2.5.9 for advisory `RUSTSEC-2026-0592`.
- Fix prefilter heap-slot cleanup during error unwinding, remove per-batch `IndexInfo` / `ExecutorState` allocations, and restore `CurrentMemoryContext` on expression evaluation errors.
- Allocate scan descriptors in `es_query_cxt`, track `pg_stat_user_indexes.idx_scan` across PostgreSQL 15–19 alongside `Index Searches` (`nsearches`) on PostgreSQL 18+, declare `amcanbuildparallel` on PostgreSQL 17+, and pass `SO_HINT_REL_READ_ONLY` and static `IndexAmRoutine` on PostgreSQL 19.
- Fix `amcostestimate` to use finite costs (avoiding `NaN` planner costs) and exclude unsupported `Index Only Scan` paths, check interrupts in `amgettuple`, and reject invalid or partitioned indexes in `bm25_maintain`.
- Preserve old-snapshot visibility when any parallel index build worker encounters a broken HOT chain. PostgreSQL can then defer use of the new index by transactions with older snapshots.
- Preserve SQL APIs and format-4 indexes when upgrading in place from 1.0.0 or 1.1.0.

Install the matching package, restart PostgreSQL, and run `ALTER EXTENSION vchord_bm25 UPDATE;` in each database. Existing 1.0.0 and 1.1.0 indexes do not require `REINDEX`.

For PostgreSQL 14 installations, upgrade PostgreSQL before installing 1.2.0. Historical 0.3.x (`bm25vector`) installations require data migration and index rebuilding.
